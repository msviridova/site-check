# Объяснение: Зависимости через App (Dependency Injection)

## Простая аналогия

Представь, что `App` — это **чемодан с инструментами**:
- В чемодане есть: база данных, AI-клиент, конфигурация
- Когда нужен инструмент, открываешь чемодан и берёшь его
- Не нужно искать инструменты по всему дому (глобальные переменные)

## Пример 1: Простая структура

```go
// Структура App - это "чемодан" с инструментами
type App struct {
    DB     *sql.DB      // Инструмент 1: База данных
    Config *Config      // Инструмент 2: Конфигурация
}

// Создаём чемодан и кладём в него инструменты
func NewApp() *App {
    db := connectToDatabase()
    config := loadConfig()
    
    return &App{
        DB:     db,      // Кладём БД в чемодан
        Config: config,  // Кладём конфигурацию в чемодан
    }
}
```

## Пример 2: Использование зависимостей

### ❌ Плохо (глобальные переменные):

```go
var db *sql.DB  // Глобальная переменная - плохо!

func getUser(id int) {
    // Откуда взялась db? Непонятно!
    db.Query("SELECT * FROM users WHERE id = ?", id)
}
```

### ✅ Хорошо (через структуру):

```go
// Метод структуры App
func (app *App) getUser(id int) {
    // Ясно: db берётся из app (из нашего "чемодана")
    app.DB.Query("SELECT * FROM users WHERE id = ?", id)
}
```

## Пример 3: Как это работает в коде

### Создание App (чемодана):

```go
func main() {
    // Создаём App со всеми зависимостями
    app, err := NewApp()
    if err != nil {
        log.Fatal(err)
    }
    defer app.Close()
    
    // Теперь у нас есть app с:
    // - app.DB (база данных)
    // - app.Config (конфигурация)
    // - app.Config.AIClient (AI клиент)
}
```

### Использование в handler:

```go
// Handler - это метод структуры App
func (app *App) classifyHandler(w http.ResponseWriter, r *http.Request) {
    // Используем зависимости из app:
    
    // 1. Берём промпт из БД
    prompt, err := app.getPrompt("classify", "ru", 0)
    //              ^^^^ метод App, который использует app.DB
    
    // 2. Используем AI клиент из конфигурации
    resp, err := app.Config.AIClient.Chat.Completions.New(...)
    //           ^^^^^^^^^^^^^^^^^^^^ AI клиент из app.Config
    
    // 3. Используем таймаут из конфигурации
    ctx, cancel := context.WithTimeout(r.Context(), app.Config.ClassifyTimeout)
    //                                                        ^^^^^^^^^^^^^^
}
```

## Пример 4: Что значит "метод структуры"

### Обычная функция:
```go
func getUser(db *sql.DB, id int) {
    db.Query(...)
}

// Вызов:
getUser(db, 123)  // Нужно передавать db каждый раз
```

### Метод структуры:
```go
func (app *App) getUser(id int) {
    app.DB.Query(...)  // db уже есть в app
}

// Вызов:
app.getUser(123)  // db уже внутри app, не нужно передавать
```

**`(app *App)` перед именем функции** — это означает, что функция является **методом** структуры `App`.

## Пример 5: Полный поток

```go
// 1. Создаём App (чемодан) в main.go
func main() {
    app, _ := NewApp()  // Создали чемодан с инструментами
    // app содержит:
    //   - DB (база данных)
    //   - Config (конфигурация с AI клиентом)
    
    // 2. Регистрируем handlers как методы App
    mux.HandleFunc("/classify", app.classifyHandler)
    //                              ^^^^ это метод App
}

// 3. Handler использует зависимости из app
func (app *App) classifyHandler(w http.ResponseWriter, r *http.Request) {
    // app.DB - база данных из структуры
    prompt, _ := app.getPrompt("classify", "ru", 0)
    
    // app.Config.AIClient - AI клиент из конфигурации
    resp, _ := app.Config.AIClient.Chat.Completions.New(...)
}
```

## Почему это лучше?

### 1. Явные зависимости
```go
// Видно, что функция нуждается в App (а в App есть все зависимости)
func (app *App) getUser(id int) {
    app.DB.Query(...)  // Ясно: нужна БД
}
```

### 2. Легко тестировать
```go
func TestGetUser(t *testing.T) {
    // Создаём тестовую БД
    mockDB := createMockDB()
    
    // Создаём App с тестовой БД
    app := &App{DB: mockDB}
    
    // Тестируем
    app.getUser(123)  // Использует mockDB, а не реальную БД
}
```

### 3. Нет глобальных переменных
```go
// ❌ Плохо: глобальная переменная
var db *sql.DB

// ✅ Хорошо: переменная внутри структуры
type App struct {
    DB *sql.DB
}
```

## Визуализация

```
main.go:
┌─────────────────────┐
│  app := NewApp()    │  ← Создаём "чемодан"
│                     │
│  app содержит:      │
│  ├─ DB              │  ← База данных
│  ├─ Config          │  ← Конфигурация
│  │  ├─ AIClient     │  ← AI клиент
│  │  ├─ ModelName    │  ← Название модели
│  │  └─ Timeouts     │  ← Таймауты
│  └─ promptCache     │  ← Кэш промптов
└─────────────────────┘
         │
         │ передаём app в handlers
         ▼
handler.go:
┌─────────────────────┐
│ (app *App)          │  ← Метод App
│ classifyHandler() { │
│                     │
│   app.getPrompt()   │  ← Использует app.DB
│   app.Config.       │  ← Использует app.Config
│     AIClient...     │
│ }                   │
└─────────────────────┘
```

## Ключевые моменты

1. **Структура App** — это контейнер для всех зависимостей
2. **Методы App** — функции, которые имеют доступ к зависимостям через `app`
3. **Нет глобальных переменных** — все хранится в структуре
4. **Явные зависимости** — видно, что нужно для работы
5. **Легко тестировать** — можно создать App с тестовыми зависимостями

## Сравнение

| Аспект | Глобальные переменные | Через структуру App |
|--------|----------------------|---------------------|
| Видны ли зависимости? | ❌ Нет | ✅ Да |
| Можно тестировать? | ❌ Сложно | ✅ Легко |
| Понятен код? | ❌ Не всегда | ✅ Да |
| Можно создать несколько экземпляров? | ❌ Нет | ✅ Да |

## Итог

**"Зависимости передаются через App"** означает:
- Все нужные инструменты (БД, клиенты, конфигурация) хранятся в структуре `App`
- Функции становятся методами `App` и имеют доступ к этим инструментам
- Вместо глобальных переменных используется структура с полями
- Это делает код более понятным, тестируемым и гибким
